## Задание 1: Анализ производительности CPU-параллельной программы (OpenMP) (Practice10_Task1.ipynb)

Цель:

Разработать параллельную программу на C++ с использованием OpenMP для обработки большого массива данных (сумма, среднее, дисперсия) и проанализировать ускорение.

Реализация:

 - Использован массив из 10 000 000 элементов.

 - Параллельные участки:

     Сумма массива — #pragma omp parallel for reduction(+:sum)

     Вычисление дисперсии — #pragma omp parallel for reduction(+:variance)

 - Профилирование через omp_get_wtime() для измерения времени выполнения.

## Задание 2: Оптимизация доступа к памяти на GPU (CUDA) (Practice10_Task2.ipynb)

Цель:

Исследовать влияние разных паттернов доступа к памяти GPU на производительность.

Реализация:

- Использован массив из 1 048 576 элементов (2^20).

 Реализованы три ядра:

 - Коалесцированный доступ — последовательный доступ потоков к соседним элементам.

 - Неко алесцированный доступ — обращение к элементам с шагом (stride), создаёт хаотический доступ к памяти.

 - Shared memory — данные сначала загружаются в быструю разделяемую память блока, затем обрабатываются.

- Время измерялось через cudaEvent_t.

# Компиляция и запуск в Google Colab:

Сохраняем программу в файл
 
%%writefile practice10_2.cpp
[код программы]

Компилируем
 
!nvcc practice10_2.cu -o practice10_2 -arch=sm_75 -std=c++11         

Запускаем

!./practice10_2

<img width="704" height="351" alt="image" src="https://github.com/user-attachments/assets/c9215e09-8447-4ed9-9414-120bd3c07779" />

Вывод: 

 - Коалесцированный доступ эффективен для глобальной памяти.

 - Shared memory даёт максимальное ускорение.

 - Плохой паттерн (не коалесцированный) значительно замедляет вычисления.

## Задание 3: Профилирование гибридного приложения CPU + GPU (Practice10_Task3.ipynb)

Цель:

Разработать программу, где часть вычислений выполняется на CPU, а часть — на GPU, и проанализировать накладные расходы передачи данных.

Реализация:

 - Массив делится пополам: первая половина на CPU, вторая половина на GPU.

 - GPU использует cudaMemcpyAsync и CUDA streams для асинхронной передачи данных.

 - CPU параллельно вычисляет сумму своей половины.

## Задание 4: Анализ масштабируемости распределённой программы (MPI) (Practice10_Task4.ipynb)

Цель:

Реализовать распределённую программу для вычисления агрегатных функций над большим массивом и оценить масштабируемость.

Реализация:

 - Массив N = 1 000 000 элементов делится между P процессами.

 - Каждый процесс считает локальные сумму, минимум и максимум.

 - Глобальные значения собираются через MPI_Reduce.

 - Время выполнения измеряется через MPI_Wtime().

# Компиляция и запуск в Google Colab:

 Сохраняем программу в файл
 
%%writefile practice10_4.cpp
[код программы]

Компилируем

!mpic++ practice10_4.cpp -o practice10_4


Запуск с 2 процессами

!mpirun --allow-run-as-root --oversubscribe -np 2 ./practice10_4

Запуск с 8 процессами

!mpirun --allow-run-as-root --oversubscribe -np 8 ./practice10_4

Запуск с 16 процессами

!mpirun --allow-run-as-root --oversubscribe -np 16 ./practice10_4

<img width="691" height="630" alt="image" src="https://github.com/user-attachments/assets/434b701b-2b15-42d8-aa19-b01893b7649c" />

Вывод:

 - MPI эффективно распределяет вычисления.

 - Время уменьшается при росте числа процессов (strong scaling).

 = Основное ограничение — накладные расходы на коммуникацию (MPI_Reduce).
